# - apparmor: inclui aa-status/aa-enforce/aa-notify/aa-logprof
# - audit: gera /var/log/audit/audit.log
# - python-notify2: notificações desktop
# - tk: requerido pelo aa-notify (tkinter/libtk)

cat /sys/kernel/security/lsm

#Grupo audit (pra permitir leitura do audit.log pelo usuário)

sudo gpasswd -a "$(whoami)" audit

#Configurar auditd para usar o grupo audit no log
sudo nano /etc/audit/auditd.conf
# Ajustar para:
log_group = audit

#Reboot (necessário para:
# - aplicar log_group com auditd protegido contra restart manual
# - aplicar membership do grupo 'audit' na sessão do usuário)

:: FORMATAR DISCO E MONTAR
# 1) Criar/editar partição com cfdisk
sudo cfdisk /dev/sda
# Dentro do cfdisk:
# - Delete (excluir) partições antigas (se necessário)
# - New (nova) -> usar tamanho total
# - Type -> Linux filesystem
# - Write -> yes
# - Quit

# 2) Validar se a partição foi criada
lsblk -f

# 3) Formatar a partição em EXT4 e definir label
sudo mkfs.ext4 -L disk-dados /dev/sda1

# 4) Criar ponto de montagem
sudo mkdir -p /mnt/disk-dados

# 5) Montar manualmente para testar
sudo mount /dev/sda1 /mnt/disk-dados

# 6) Confirmar se montou
df -h | grep sda

# 7) Pegar UUID do disco
sudo blkid /dev/sda1

# 8) Editar fstab para montar automaticamente no boot
sudo nano /etc/fstab

# Adicionar no final do arquivo:
# UUID=2db45c18-e2a4-449f-897b-37d34141181c  /mnt/disk-dados  ext4  defaults,noatime  0  2

# 9) Recarregar systemd (se aparecer aviso após editar fstab)
sudo systemctl daemon-reload

# 10) Testar montagem automática sem reiniciar
sudo umount /mnt/disk-dados
sudo mount -a

# 11) Validar montagem novamente
df -h | grep sda

# 12) Ajustar permissões para permitir escrita pelo usuário
sudo chown -R $USER:$USER /mnt/disk-dados

# 13) Testar criação de arquivo
touch /mnt/disk-dados/teste.txt
ls -l /mnt/disk-dados/teste.txt

# 14) Validar final
lsblk -f | grep sda

#Criar configuração Snapper para ROOT (/) e HOME (/home)
sudo snapper -c root create-config /
sudo snapper -c home create-config /home

#Ajustar permissões e ACL do Snapper
sudo snapper -c root set-config "ALLOW_USERS=$USER" "SYNC_ACL=yes"
sudo snapper -c home set-config "ALLOW_USERS=$USER" "SYNC_ACL=yes"

#Desativar snapshots automáticos no /home (timeline)
sudo snapper -c home set-config "TIMELINE_CREATE=no"

#Habilitar timers do Snapper

Correção do tuned-adm verify no Arch Linux
==========================================

Problema
--------
Em sistemas com amd-pstate-epp, o comando:

sudo tuned-adm verify

pode falhar com erro relacionado ao módulo cpufreq_conservative,
mesmo com o TuneD funcionando corretamente.

Causa
-----
O perfil "desktop" herda o perfil "balanced".
O perfil "balanced" original tenta validar cpufreq_conservative.
No Arch com amd-pstate-epp, isso pode gerar falso erro no verify.

Correção
--------
1) Criar o diretório do perfil local override:

sudo mkdir -p /etc/tuned/profiles/balanced

2) Editar o arquivo:

sudo nano /etc/tuned/profiles/balanced/tuned.conf

3) Colar este conteúdo:

[main]
include=balanced

[modules]
enabled=0

4) Reiniciar os serviços:

sudo systemctl restart tuned tuned-ppd

5) Validar novamente:

sudo tuned-adm verify

Resultado esperado
------------------
Verification succeeded, current system settings match the preset profile.

:: Criar Converter MKV to MP4 no contexto do dolphin

# 1) Criar pasta local de scripts
mkdir -p ~/.local/bin

# 2) Criar o script que converte MKV para MP4
cat > ~/.local/bin/mkv-to-mp4 <<'EOF'
#!/usr/bin/env bash
set -euo pipefail

need() {
  command -v "$1" >/dev/null 2>&1 || {
    echo "Erro: '$1' não encontrado."
    exit 1
  }
}

need ffmpeg
need notify-send

if [[ $# -lt 1 ]]; then
  notify-send "MKV para MP4" "Nenhum arquivo foi informado."
  exit 1
fi

for input in "$@"; do
  [[ -f "$input" ]] || continue

  ext="${input##*.}"
  shopt -s nocasematch
  if [[ "$ext" != "mkv" ]]; then
    shopt -u nocasematch
    continue
  fi
  shopt -u nocasematch

  dir="$(dirname "$input")"
  base="$(basename "$input")"
  name="${base%.*}"
  output="$dir/$name.mp4"

  if [[ -e "$output" ]]; then
    output="$dir/${name}_convertido.mp4"
  fi

  # Mantém o vídeo original e converte só o áudio para AAC
  if ffmpeg -y -i "$input" -c:v copy -c:a aac -b:a 128k "$output"; then
    notify-send "MKV para MP4" "Conversão concluída: $(basename "$output")"
  else
    notify-send "MKV para MP4" "Falha ao converter: $(basename "$input")"
  fi
done
EOF

# 3) Garantir que o script pertence ao seu usuário
sudo chown $USER:$USER ~/.local/bin/mkv-to-mp4

# 4) Dar permissão de execução ao script
chmod +x ~/.local/bin/mkv-to-mp4

# 5) Criar a ação do menu de contexto do Dolphin
mkdir -p ~/.local/share/kio/servicemenus
cat > ~/.local/share/kio/servicemenus/mkv-to-mp4.desktop <<EOF
[Desktop Entry]
Type=Service
MimeType=video/x-matroska;
Actions=ConvertMKVtoMP4
X-KDE-ServiceTypes=KonqPopupMenu/Plugin

[Desktop Action ConvertMKVtoMP4]
Name=Converter MKV para MP4
Name[pt_BR]=Converter MKV para MP4
Icon=video-x-generic
Exec=$HOME/.local/bin/mkv-to-mp4 %F
EOF

# 6) Dar permissão de execução ao arquivo .desktop
chmod +x ~/.local/share/kio/servicemenus/mkv-to-mp4.desktop

# 7) Fechar e abrir o Dolphin novamente
# Depois disso, ao clicar com o botão direito em um arquivo .mkv,
# deve aparecer a opção:
# Converter MKV para MP4

CONFIGURAÇÃO VORTA BACKUP - ARCH LINUX -> UNRAID VIA NFS

Objetivo:
Backup dos arquivos pessoais do Arch Linux usando Vorta/Borg, salvando no Unraid via NFS.

Pacotes instalados no Arch:
- vorta
- nfs-utils

Comando de instalação:
sudo pacman -S vorta nfs-utils

------------------------------------------------------------
1. Share no Unraid
------------------------------------------------------------

Servidor Unraid:
192.168.15.200

Share usado:
backup

Caminho real no Unraid:
/mnt/user/backup

Pasta criada para o Vorta:
/mnt/user/backup/vorta-backup

Configuração NFS no Unraid:
Shares > backup > NFS Security Settings

Export:
Yes

Security:
Private

Rule:
*(rw,no_root_squash)

------------------------------------------------------------
2. Criar ponto de montagem no Arch
------------------------------------------------------------

Criar pasta local:

sudo mkdir -p /mnt/unraid-backup

Validar export NFS do Unraid:

showmount -e 192.168.15.200

Resultado esperado:
Export list for 192.168.15.200:
/mnt/user/backup *

Montar manualmente para teste:

sudo mount -t nfs -o vers=4 192.168.15.200:/mnt/user/backup /mnt/unraid-backup

Validar montagem:

findmnt /mnt/unraid-backup

Resultado esperado:
SOURCE:
192.168.15.200:/mnt/user/backup

FSTYPE:
nfs4

Listar conteúdo:

ls -lah /mnt/unraid-backup

Deve aparecer:
vorta-backup

------------------------------------------------------------
3. Montagem automática no boot via /etc/fstab
------------------------------------------------------------

Editar fstab:

sudo nano /etc/fstab

Adicionar no final:

#nfs unraid-backup
192.168.15.200:/mnt/user/backup  /mnt/unraid-backup  nfs  defaults,_netdev,vers=4,nofail,x-systemd.automount  0  0

Aplicar e testar:

sudo systemctl daemon-reload
sudo mount -a
findmnt /mnt/unraid-backup

Observação:
Com x-systemd.automount, o NFS não precisa montar imediatamente no boot.
Ele monta automaticamente quando algum processo acessar:

/mnt/unraid-backup

Isso evita travar o boot se o Unraid estiver desligado ou se a rede ainda não estiver pronta.

------------------------------------------------------------
4. Configuração do repositório no Vorta
------------------------------------------------------------

Abrir Vorta:

vorta

Criar novo profile:
unraid-backup

Criar novo repositório local, usando o caminho:

/mnt/unraid-backup/vorta-backup

Observação:
Não usar SSH neste cenário.

Não usar:
ssh://root@192.168.15.200/mnt/user/backup/vorta-backup

Motivo:
Via SSH o Borg precisaria estar instalado também no Unraid.
Como estamos usando NFS, o Vorta/Borg trabalha como se fosse uma pasta local.

O Borg/Vorta não cria uma pasta separada para cada backup.

integrity.*

Não mexer manualmente dentro dessa pasta.

O Borg usa deduplicação.
Primeiro backup copia tudo.
Próximos backups salvam somente diferenças/blocos alterados.

# Fix suspend - Gigabyte B550M AORUS ELITE
# Desabilita wake via PCIe Root Port e controlador USB PCIe problemático
#
# GPP0 -> PCI Root Port
# PTXH -> USB xHCI Controller 0000:02:00.0
#
# Solução para:
# - wake imediato após suspend
# - instabilidade ACPI resume
# - xHCI USB resume problemático

sudo nano /etc/systemd/system/disable-gpp0-wake.service

[Unit]
Description=Disable problematic PCI wake devices

[Service]
Type=oneshot
RemainAfterExit=yes
ExecStart=/bin/sh -c 'echo GPP0 > /proc/acpi/wakeup; echo PTXH > /proc/acpi/wakeup'

[Install]
WantedBy=multi-user.target

sudo systemctl daemon-reload
sudo systemctl enable disable-gpp0-wake.service
sudo systemctl restart disable-gpp0-wake.service
